II.  Abstract

This OGC Community Standard specifies formal RDF, RDFS, OWL, and SKOS vocabulary alignments between the OGC GeoSPARQL ontology (http://opengis.net) and widely adopted external geospatial, Linked Data, and domain vocabularies. These machine-readable mappings enable semantic interoperability, federated querying, and cross-ontology reasoning across heterogeneous spatial knowledge graphs.

V.  Introduction

The OGC GeoSPARQL standard provides a foundational ontology and SPARQL extension for representing and querying spatial features, geometries, and topological relations on the Semantic Web. In practice, spatial datasets frequently describe geographic entities using established domain vocabularies—such as W3C Basic Geo (geo_pos), Schema.org, CIDOC CRM, PROV-O, Dublin Core Terms, or regional spatial data infrastructures—alongside or instead of core GeoSPARQL classes and properties.

This document defines the GeoSPARQL Vocabulary Alignments, a curated collection of declarative mapping axioms maintained by the OGC GeoSPARQL Standards Working Group (SWG). Rather than requiring data publishers to rewrite existing RDF graphs, these alignments establish formal semantic bridges between GeoSPARQL terms and external ontologies.

V.A.  Purpose and Role of Vocabulary Alignments

Providing standardized ontology alignments supports three primary interoperability patterns:

  • Automated Reasoning and Inference: OWL and RDFS axioms (owl:equivalentClass, owl:equivalentProperty, rdfs:subClassOf, rdfs:subPropertyOf) allow OWL/RDFS reasoners to infer GeoSPARQL types and spatial properties from existing domain triples automatically.

  • Cross-Vocabulary Query Translation: Mapping relationships enable SPARQL query engines and middleware to rewrite or federate spatial queries across datasets modeled with different schemas.

  • Semantic Discovery and Mapping Clarity: SKOS mapping properties (skos:exactMatch, skos:closeMatch, skos:broadMatch, skos:narrowMatch, skos:relatedMatch) document conceptual correspondences where strict logical equivalence does not hold due to differing ontological commitments.

V.B.  Structure of This Document

Each alignment module in this specification is generated directly from normative Turtle (.ttl) mapping files maintained in the OGC Geosemantics Semantic Resources repository. For every target vocabulary, this document provides:

  1. Namespace Prefix Overview: A summary table of all RDF namespaces and prefixes referenced across the alignment modules.

  2. Vocabulary Alignment Sections: Dedicated subsections detailing the source GeoSPARQL terms, alignment predicates, target vocabulary terms, and explanatory scope notes. == Scope

This OGC Community Standard specifies declarative vocabulary alignments between classes and properties of the OGC GeoSPARQL ontology and external RDF/OWL/SKOS vocabularies.

The scope of this document includes:

  • Canonical namespace bindings and vocabulary metadata for each GeoSPARQL alignment module;

  • Normative and informative mapping axioms expressed using RDFS, OWL, and SKOS predicates;

  • Governance procedures for proposing and maintaining new vocabulary alignments via the OGC GeoSPARQL Standards Working Group.

This document does not modify the core GeoSPARQL ontology or redefine the semantics of external target vocabularies.

1.  Conformance

This standard defines conformance requirements for RDF alignment graphs and reasoning profiles that implement the GeoSPARQL vocabulary mappings specified in this document.

Example — GeoSPARQL Vocabulary Alignment

Target: RDF graphs and semantic middleware applying GeoSPARQL vocabulary alignments.

Requirement: /req/vocabulary-alignment/axiom-consistency

Test method: Inspect the alignment graph and entailed triples to verify that:

  1. All GeoSPARQL source terms use canonical IRIs within the http://opengis.net or http://opengis.net namespaces.

  2. Each mapping triple uses a recognized alignment predicate (owl:equivalentClass, owl:equivalentProperty, rdfs:subClassOf, rdfs:subPropertyOf, or a skos:*Match property).

  3. Applying the RDFS/OWL alignment axioms to a valid source graph produces no logical inconsistencies under OWL 2 DL or RDFS entailment regimes.

3.1.  Ontology Alignment

set of correspondences between entities (classes, properties, or concepts) belonging to two or more distinct ontologies or vocabularies

3.2.  Equivalence Axiom

OWL statement (owl:equivalentClass or owl:equivalentProperty) asserting that two classes or properties share identical extensions

[SOURCE: W3C OWL 2]

3.3.  Subsumption Axiom

RDFS statement (rdfs:subClassOf or rdfs:subPropertyOf) asserting that all instances or pairs of a source term are also instances or pairs of a broader target term

[SOURCE: W3C RDF Schema 1.1]

3.4.  Conceptual Mapping

SKOS mapping assertion (skos:exactMatch, skos:closeMatch, skos:broadMatch, skos:narrowMatch, or skos:relatedMatch) indicating semantic similarity between concepts across distinct schemes without enforcing OWL logical entailment

[SOURCE: W3C SKOS]

4.  Contributing New Alignments

The GeoSPARQL Vocabulary Alignments are maintained openly on GitHub by the OGC GeoSPARQL Standards Working Group in the OGC Geosemantics Semantic Resources repository.

Community members and ontology maintainers may propose new vocabulary alignments or revisions to existing mappings by opening an issue at https://github.com/issues with the target vocabulary IRI, proposed Turtle mapping triples, and rationale for the chosen alignment predicates.
