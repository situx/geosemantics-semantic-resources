II.  Abstract

This OGC Community Standard defines the GeoSPARQL Geometry Datatype Registry, a curated set of RDF literal datatypes (rdfs:Datatype) and accompanying serialization properties maintained by the OGC GeoSPARQL Standards Working Group (SWG). These datatypes enable standardized representation of 2D, 3D, discrete global grid, and web-native geometry serializations within RDF and SPARQL ecosystems.

V.  Introduction

The OGC GeoSPARQL standard defines a vocabulary and query language for representing and querying geospatial data in the Resource Description Framework (RDF) and SPARQL. While core GeoSPARQL establishes foundational geometry serializations such as Well-Known Text (geo:wktLiteral) and Geography Markup Language (geo:gmlLiteral), modern geospatial workflows rely on a diverse ecosystem of domain-specific, web-native, and 3D geometry encodings.

This Community Standard documents the GeoSPARQL Geometry Datatype Registry, providing standardized Internationalized Resource Identifiers (IRIs), formal definitions, and metadata for representing diverse spatial formats directly within RDF graphs.

V.A.  Registry Overview

The datatypes specified in this document extend GeoSPARQL interoperability across multiple geospatial communities without altering the core GeoSPARQL ontology:

  • 2D and Vector Web Formats: Encodings optimized for web APIs, lightweight exchange, and structured data, including GeoJSON, JSON-FG, GeoYAML, and GPX.

  • Binary and Discrete Spatial Representations: Compact and grid-based serializations such as Well-Known Binary (WKB), Discrete Global Grid Systems (DGGS), and geocoded identifiers.

  • 3D and Visualization Formats: Geometry serializations supporting 3D scenes, meshes, and Earth-browsing applications, including KML, glTF, OBJ, PLY, and X3D.

V.B.  Registry Structure

Each entry in the registry is maintained as a machine-readable Turtle (.ttl) resource in the OGC Geosemantics Semantic Resources repository. For every registered geometry format, this document specifies:

  1. Datatype Definition: The canonical IRI, human-readable label, formal scope definition, and semantic metadata (rdfs:Datatype attributes).

  2. Accompanying Properties: Associated RDF serialization properties (such as subproperties of geo:hasSerialization) that link geo:Geometry instances to literals typed with the corresponding datatype.

By establishing persistent, dereferenceable datatype IRIs and consistent property patterns, this registry enables data publishers, triple stores, and client applications to unambiguously declare, validate, and exchange specialized geometry literals in Linked Data environments. == Scope

This OGC Community Standard specifies Internationalized Resource Identifiers (IRIs), formal definitions, and accompanying RDF serialization properties for geometry literal datatypes (rdfs:Datatype) used in conjunction with OGC GeoSPARQL.

The scope of this document includes:

  • Canonical IRIs and semantic metadata for geometry literal datatypes registered by the OGC GeoSPARQL Standards Working Group;

  • Accompanying RDF datatype properties linking geo:Geometry instances to typed geometry literals;

  • Governance and community contribution procedures for proposing new geometry literal datatypes to the registry.

This document does not define new spatial topological functions, query operators, or geometry-format-specific syntax rules beyond those specified by the underlying encoding standards referenced by each datatype. == Conformance

This standard defines conformance requirements for RDF datasets and vocabularies that use geometry literal datatypes and serialization properties from the GeoSPARQL Geometry Datatype Registry.

Example — Registry Datatype Usage

Target: RDF datasets and vocabularies serializing geometries using registry datatypes.

Requirement: /req/datatype-usage/iri-and-syntax

Test method: Inspect RDF triples containing geometry literals to verify that:

  1. Each geometry literal is typed with the exact canonical rdfs:Datatype IRI defined in this registry.

  2. The lexical form of each typed literal conforms to the syntax and encoding specification referenced by that datatype.

  3. Where an accompanying serialization property is defined in this registry for the datatype, geo:Geometry instances link to the typed literal using that property or a valid subproperty thereof.

1.4.  Proposing a New Geometry Literal Datatype

Community members, data publishers, and software implementers may propose new geometry literal datatypes or updates to existing definitions by opening an issue in the repository:

  • Issue Tracker: https://github.com/issues

When submitting an issue to propose a new literal type, contributors should provide:

  1. Format Name and Specification: The name of the geometry serialization format and a link to its authoritative specification or standard.

  2. Proposed Datatype IRI and Label: A suggested canonical IRI (e.g., within the http://opengis.net namespace) and a concise human-readable rdfs:label.

  3. Scope Definition: A clear description (skos:definition or rdfs:comment) explaining the encoding, coordinate reference system handling, and intended use cases.

  4. Accompanying Serialization Property: Details of the corresponding RDF property (such as geo:has<Format>) to associate geo:Geometry instances with literals of the proposed datatype.

  5. Example Literal: A brief, valid RDF Turtle example demonstrating the datatype and serialization property in use.

1.5.  Review and Publication Process

Submitted issues are reviewed by the OGC GeoSPARQL SWG for technical clarity, alignment with existing GeoSPARQL conventions, and absence of duplication. Once approved, a corresponding Turtle (.ttl) definition file is added to the resources/geosparql-swg/geosparql-geometry-datatypes/resources directory, and this Community Standard document is automatically regenerated and published via Continuous Integration.
